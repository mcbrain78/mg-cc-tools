# Non-Goals for concept.md

- No changes to mg:spec-improve **review** behavior (review loop, fix cap, approval flow) — it remains the manual path by design; from this concept it inherits only the shared improve_files.py hardening plus the minimal Setup resume branch that hardening forces (guard failure → paths → resume or --fresh). Note: spec-improve's Step-5 per-fix inline-comment convention was retired in a *separate* change, so its working copies no longer accumulate inline fix-annotations (its audit trail is the round report plus git); called out here only so this bullet is not misread as implying that convention is still live. This design's CHANGELOG-sidecar approach is unaffected.
- No concept-spec-template changes — specifically no scope↔verification link syntax to make coverage checking deterministic.
- No spec-create-milestone consumption of concept-IMPLEMENTER-NOTES.md — the sidecar is advisory for the implementer in this version.
- No divergence detection for hand-edits to the original during discussion pauses — same exposure exists in spec-improve today.
- No token budget mechanism — cost is accepted at this leverage point; the round cap is the only brake.
- No analysis tooling for run history — history/ is raw material; hindsight analysis (gate tuning, churn review) stays ad-hoc.
- No simplification or removal of the competitive section-rewrite mechanism — the two-rewrite + panel-vote duo for whole-anchor-unit macro fixes is intentionally retained for redundancy at the highest-stakes (hardest-to-undo) structural edits, despite the D12 scoped re-check and churn escalation as a downstream backstop (considered and kept, round-13). Genuine correctness bugs in the mechanism remain fair game.
- No hybrid-first build order or A/B-against-hybrid benchmark — the pyramid-vs-ledger architecture is settled (D3); the no-ledger hybrid is the named fallback, triggered by the first real run's convergence data (D4, D11), not built in parallel for comparison. Its falsifiability is now pinned (spike = accounting fidelity, first real run = convergence value); a genuine break in that falsification mechanism stays fair game.
- No simplification or removal of the decision dependency-DAG (depends_on) — the render-time mechanical edges (post-take-radius overlap plus id order), stored semantic edges, and cycle-breaking tiebreak are intentionally retained per D9: they make an override's cascade visible (reversing a root decision shows its affected dependents) and catch dependencies the blast-radius rule cannot see, which plain radius-ranking of the briefing cannot replicate (considered and kept, spec-improve round 1). Genuine correctness bugs in the edge/cycle logic remain fair game.
