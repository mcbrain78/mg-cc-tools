## Phase Boundary

The generate step creates or updates all audience-segmented documents section-by-section using templates and scan results. This is the `/mg:create-docs-generate` command — the only pipeline step that writes documentation files.

</domain>

<decisions>
## Implementation Decisions

### Initial Mode — Section-by-Section Generation (GEN-01)
- For each document, generate section-by-section following the three-layer template
- Per section: (1) read template heading + purpose + example, (2) read source material mapped to this section from scan, (3) generate content, (4) next section
- Sequential within an agent, parallel across audiences
- Agents receive file paths only, read files themselves — no pasting of templates/source material into agent prompts *(from milestone discussion)*

### Update Mode — Staleness-Driven Updates (GEN-02)
- Interactive approval flow:
  1. **Overview**: document-level counts + severity grouping (e.g., "ARCHITECTURE.md: 3 stale sections (2 critical, 1 warning)")
  2. **User choice**: approve all, approve by document, or approve by severity level
  3. **Drill-in** (if user selects by document): section name + reason + changed files per stale section
  4. **Inbox notes**: shown in same flow as a separate group after staleness sections, same approve-all/drill-in pattern
- Generate only approved sections, feeding source material per section
- No memory of rejections between runs — rejected sections reappear next run

### Notes Integration (GEN-03)
- During generate step, classified notes are:
  1. Presented in the update approval flow (same interactive pattern, grouped separately)
  2. Expanded from raw note into proper prose matching target document style
  3. Inserted at classified location
  4. Marked as `"status": "integrated"` in inbox with integration date

### Section Ownership Tracking (GEN-04)
- Each generated section includes an HTML comment marker: `<!-- docs-meta: last-updated: YYYY-MM-DD, sources: [file1.py, file2.py] -->`
- Tells future scans which code files drive this section and when it was last generated
- Enables staleness detection in subsequent scan runs

### File Ownership Header
- Each generated file starts with: `<!-- This file is auto-generated by /mg:create-docs. To add content, use /mg:add-docs. Manual edits may be overwritten. -->`
- `docs/auto-doc/` is machine-owned — manual edits at user's own risk
- Users add content via `/mg:add-docs` (notes inbox), not by editing generated files

### Cross-Document Consistency (GEN-05)
- Glossary agent runs first from scan results, establishes shared vocabulary baseline
- Writer agents receive the glossary as input for terminology consistency
- Writers propose new terms only (term + one-line context note) — glossary agent writes all definitions
- Glossary reconciliation happens within the same run after writers complete
- Reconciliation also flags term inconsistencies across writer output — flagged issues go into verify report

### Generate Execution Order
- (1) Glossary agent first from scan results — builds initial glossary
- (2) 4 writer agents in parallel using glossary as input
- (3) Glossary reconciliation pass — add proposed terms + flag inconsistencies across writers
- (4) OVERVIEW.md generated last — ensures accurate audience routing

### Document Types (DOC-01 through DOC-13, excluding DOC-04)
- Output directory: `docs/auto-doc/` committed to git
- Shared (root): OVERVIEW.md (DOC-01), GLOSSARY.md (DOC-02)
- End-users: USER_GUIDE.md (DOC-03)
- Developers: ARCHITECTURE.md (DOC-05), DEVELOPER_GUIDE.md (DOC-06), QUICK_REFERENCE.md (DOC-07)
- Agents: SYSTEM_MAP.md (DOC-08), CONVENTIONS.md (DOC-09), GOTCHAS.md (DOC-10), TESTING.md (DOC-11)
- DevOps: OPERATIONS.md (DOC-12), TROUBLESHOOTING.md (DOC-13)
- DOC-04 (custom/domain-specific documents) deferred to v2

### Writer Agent Execution
- Each writer agent receives file paths to: audience-specific templates, source material index entries from scan, current doc content (if update mode), glossary, style guide
- Agents read files themselves — no content pasted into agent prompts

### Generate Command (CMD-03)
- Command: `/mg:create-docs-generate`
- Writes docs — the only pipeline step that modifies documentation files
- Two modes: initial (no existing docs) and update (docs exist)
- Tool installs to `.claude/create-docs/` — generate command references templates at `.claude/create-docs/references/templates/`

### Generation Progress Feedback
- Stage-level updates during generation: one line per stage ("Building glossary...", "Writing docs (4 agents)...", "Reconciling terms...", "Generating OVERVIEW.md...")
- Post-generation summary: list each generated/updated file with section count and word count
- Update mode: distinguish changed vs unchanged documents in summary
- After completion: suggest `/mg:create-docs-verify` as next step

### Road-Runner Validation
- Phase success criteria includes: generate must produce usable docs when run on `../road-runner`

### Claude's Discretion
- Section-by-section generation protocol details (how context is managed per section)
- How to handle sections that span multiple source files
- Error handling when source material is insufficient for a section

</decisions>

<specifics>
## Specific Ideas

- Follow codebase-health patterns for parallel agent coordination:
  - How subagents receive work + write output: `codebase-health/agents/implementor.md`
  - Status tracking during multi-agent work: `codebase-health/scripts/update-findings.py`
  - Parallel agent coordination: `codebase-health/commands/codebase-health-scan.md` (agent spawning section)
- Key difference from codebase-health: Step 2 is creative (writing docs), not diagnostic — templates drive generation instead of agent specialization alone
- The `docs-meta` HTML comment format is a fixed contract between generate and scan steps

</specifics>
