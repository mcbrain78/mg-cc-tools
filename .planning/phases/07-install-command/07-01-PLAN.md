  <behavior>
    ## scan-status subcommand
    - Discovers only directories with BOTH tool.toml AND install.sh
    - Ignores directories missing either file
    - Reads tool.toml fields: tool.description, tool.exclude, preflight.required, preflight.optional (defaults for missing fields)
    - Reads project version from pyproject.toml via tomllib
    - Computes SHA256 checksums of source files using include scope: commands/*, scripts/*.py, scripts/lib/*.py, agents/*.md, references/**/*, install.sh
    - Excludes from checksums: tool.toml, tests/, **/tests/, __pycache__/, *.pyc, .pytest_cache/
    - Reports status "available" when no manifest entry exists
    - Reports status "current" when version matches AND all checksums match
    - Reports status "update" when manifest version differs from pyproject.toml version
    - Reports status "modified" when same version but checksums differ (reports changed_files list)
    - Reports status "corrupt" when manifest entry exists but command files missing in target
    - Excluded tools have excluded=true in output, separate from regular tools
    - Output JSON has: mg_cc_tools_version, target, manifest_exists, tools array, summary counts

    ## update-manifest subcommand
    - Creates manifest file if it does not exist
    - Updates existing manifest preserving other tools' entries
    - Writes atomically using tempfile + os.replace
    - Uses fcntl.flock for advisory file locking to prevent concurrent corruption
    - Records: version, installed_at (ISO 8601), commands list (*.md files from commands/), source_checksums
    - Sets top-level mg_cc_tools_version and source_path
    - source_checksums keys are relative paths within the tool directory

    ## preflight subcommand
    - Aggregates required and optional checks from tool.toml files for given tool list
    - Runs command-based checks (python3 --version, git --version, ruff --version, etc.)
    - Runs path-exists checks (gsd: checks {target}/.claude/get-shit-done)
    - Skips claude_probe type checks (lsp) -- those are handled by the LLM in install.md
    - Returns pass/fail per check with version string where available
    - Returns fix instructions per platform for failed checks
    - Distinguishes required vs optional failures

    ## validate subcommand
    - Scans installed files in target for unresolved {PLACEHOLDER} patterns (regex: \{[A-Z_]+\})
    - Verifies absolute paths found in installed command/agent files actually exist on disk
    - Checks workspace directories (.mg/docs/, .mg/health-scan/) exist for tools that scaffold them
    - Returns issues array with file, line, type (placeholder/missing_path/missing_workspace)

    ## adopt subcommand
    - Scans source tool commands/ directories to build command-to-tool mapping
    - Checks which command files exist in target's .claude/commands/mg/
    - Tool is "detected" if ALL its command files are present
    - Builds manifest entries for detected tools using current source checksums
    - Returns JSON with adopted tools and their entries
  </behavior>
