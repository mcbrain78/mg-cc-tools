<task type="auto">
  <name>Task 1: Create install.md slash command prompt</name>
  <files>install/commands/install.md</files>
  <action>
    Create `install/commands/install.md` -- the LLM instruction prompt for `/mg:install`.

    Frontmatter:
    ```yaml
    name: mg:install
    description: Install, update, and manage mg-cc-tools in target projects
    allowed-tools: Bash, Read, Write, Glob, Grep, AskUserQuestion
    ```

    The command MUST implement the full 8-step interactive flow from CONTEXT.md:

    **Step 1 - Target Selection:**
    - If $ARGUMENTS contains a path, use it directly
    - Otherwise, read `~/.config/mg-cc-tools/targets.json` for recent targets
    - Present via AskUserQuestion with recent targets + "Current directory" + manual entry option
    - Validate target path exists and has a .claude/ directory (or offer to create)
    - Update targets.json with selected target (most recent first, max 5 entries)

    **Step 2 - Status Scan:**
    - Run `mg-install-lib.py scan-status --source ./ --target <target>`
    - Format output as text table matching the mockup in CONCEPT.md
    - Columns: Tool, Description, Updated (from git log -1), Status
    - Excluded tools shown below separator with "- Excluded" marker
    - Summary line: Installed: N/M | Outdated: N | Modified: N | etc.
    - If manifest does not exist and commands found in target, suggest migration (Step 2b):
      - Run `mg-install-lib.py adopt --source ./ --target <target>`
      - Show adopted tools, then re-run scan-status for updated view

    **Step 3 - Action Selection:**
    - Present numbered options as PLAIN TEXT (NOT AskUserQuestion -- locked decision)
    - Options are context-aware based on scan results:
      - Scenario A (nothing installed): [1] Install all, [2] Select specific
      - Scenario B (some outdated/modified): [1] Update N outdated, [2] Update + install missing, [3] Install missing only, [4] Check capabilities only
      - Scenario C (all current): [1] Install remaining, [2] Reinstall all, [3] Check capabilities only
    - Parse user response: number, tool names, "all", or free text
    - Build final tool list from user selection

    **Step 4 - Preflight Checks:**
    - Run `mg-install-lib.py preflight --source ./ --target <target> --tools <tool-list>`
    - Display results with checkmarks/crosses per check
    - If any required check fails: hard abort with fix instructions (per platform)
    - If optional checks fail: warn, note degraded features, continue

    **Step 5 - Capability Probe:**
    - Run from TARGET directory (cd to target first): `claude -p --output-format json "Try to use the LSP tool to look up any symbol definition in this project. Report ONLY a JSON object: {\"lsp_functional\": true/false, \"languages\": [...]}"` with 60-second timeout
    - Handle timeout (treat as LSP not available)
    - Handle parse errors (treat as LSP not available)
    - Display result (functional with languages, or not available with degradation note)
    - Never blocking -- LSP unavailability does not prevent install

    **Step 6 - Execute Installs:**
    - For each selected tool, run its install.sh: `bash <tool>/install.sh --target <target>`
    - Display progress per tool (tool name, result, file counts)
    - install.sh handles all file copying, sed resolution, scaffolding, and manifest update
    - If a tool's install.sh fails, report error and continue with remaining tools

    **Step 7 - Post-Install Validation:**
    - Run `mg-install-lib.py validate --target <target>`
    - Display results (clean = all checkmarks, issues = list with file and problem)
    - Validation issues are warnings (the install already happened)

    **Step 8 - Summary:**
    - Format summary matching CONCEPT.md mockup
    - Show: target, per-tool action (Installed/Updated/Unchanged), command counts
    - Show capabilities section (LSP status, missing optional tools)
    - Show manifest location
    - Update targets.json with this target

    **Key constraints (from locked decisions):**
    - Runs from mg-cc-tools directory ONLY -- source is always `./`
    - Use `{SCRIPTS_DIR}` placeholder for mg-install-lib.py path (resolved by install.sh at install time -- but since this command runs from mg-cc-tools dir, use relative path `./install/scripts/mg-install-lib.py` directly)
    - Actually: since /mg:install always runs from mg-cc-tools, the script path is always `./install/scripts/mg-install-lib.py`. No sed resolution needed for this command.
    - LLM parses user's free-text response in Step 3 -- no structured parsing required
    - claude -p probe runs from TARGET directory, not source
  </action>

    ```
    # Self-installs the /mg:install command into a Claude Code configuration.

    # itself is the source repo and does not need a manifest entry.
    ```

    New machine setup workflow:
    ```bash
    cd mg-cc-tools
    ./install/install.sh --project    # bootstrap the installer
    ```
