<objective>
Modify all 11 existing install.sh scripts to call mg-install-lib.py update-manifest after every install, and add python3 checks where missing.

Purpose: Every install.sh must update the manifest -- this is the invariant that prevents brownfield scenarios. Without this, standalone installs (running install.sh directly) would not be tracked in the manifest, breaking staleness detection and status reporting.

Output: 11 modified install.sh files, each with manifest update call at end and python3 check where needed.
</objective>

<interfaces>
<!-- update-manifest interface from mg-install-lib.py -->
```bash
# Called at the end of every install.sh, after all copies and sed resolution
TOOL_SOURCE_DIR="$(cd "$(dirname "$0")" && pwd)"
python3 "${TOOL_SOURCE_DIR}/../install/scripts/mg-install-lib.py" \
  update-manifest \
  --target "$TARGET_DIR" \
  --tool "$(basename "$TOOL_SOURCE_DIR")" \
  --source "$TOOL_SOURCE_DIR"
```

<!-- python3 check (for tools missing it) -->
```bash
if ! command -v python3 &>/dev/null; then
  echo "Error: python3 is required. Install it and re-run."
  exit 1
fi
```

    The manifest update block for each script:

    ```bash
    # ── Update manifest ──────────────────────────────────────────────────────────
    TOOL_SOURCE_DIR="$(cd "$(dirname "$0")" && pwd)"
    python3 "${TOOL_SOURCE_DIR}/../install/scripts/mg-install-lib.py" \
    ```

    - Place BEFORE the summary echo block, AFTER all copies/sed/scaffolding

    - This pattern works for ALL 11 tools because they are all siblings of the `install/` directory

The manifest update call still uses python3, so if python3 is truly missing, the manifest update will fail and the install will fail.
