**create-docs/scripts/__init__.py** -- empty package marker.

**create-docs/scripts/lib/__init__.py** -- empty package marker.

**create-docs/scripts/lib/json_io.py** -- Shared JSON I/O utilities:
- `load_json(path, default=None)` -- Load JSON from path, return `default` if file doesn't exist. Use `encoding="utf-8"`.
- `save_json(path, data)` -- Atomic write: `os.makedirs` for parent dir, write to `path + ".tmp"`, then `os.replace(tmp, path)`. Use `json.dump` with `indent=2, ensure_ascii=False`, write trailing newline.
- Only stdlib imports: `json`, `os`.
- Follow the exact pattern from `codebase-health/scripts/add-finding.py` (the `load_json`/`save_json` functions there).

**create-docs/scripts/lib/git_helpers.py** -- Git subprocess wrappers:
- `git_log_since(path, since_date, repo_root=None)` -- Run `git log --format="%H %ai" --since={since_date} -- {path}`. Return list of `(commit_hash, date_str)` tuples. If `repo_root` provided, use as `cwd`.
- `git_file_changed_since(path, since_date, repo_root=None)` -- Returns `True` if any commits exist for `path` since `since_date`. Uses `git_log_since` internally.
- `git_last_modified(path, repo_root=None)` -- Run `git log -1 --format="%ai" -- {path}`. Return ISO date string or `None` if no git history.
- All subprocess calls MUST use `capture_output=True, text=True, encoding="utf-8"` to avoid encoding issues.
- Handle `subprocess.CalledProcessError` gracefully -- return empty results, not exceptions.
- Only stdlib imports: `subprocess`, `os`.

**create-docs/scripts/tests/__init__.py** -- empty package marker.

Each script file must have a module docstring explaining its purpose and noting "Zero external dependencies -- stdlib only."

**create-docs/references/schema.md** -- Define the complete `docs-scan.json` data contract following the structured-markdown format used by `codebase-health/references/schema.md`. Include:

Top-level fields (per CONTEXT.md locked decisions):
- `project` (string) -- project name
- `scan_date` (ISO 8601 string) -- when scan was performed
- `root_path` (string) -- absolute path to project root
- `mode` (enum: "initial" | "update") -- scan mode
- `project_model` (object) -- containing:
  - `tech_stack` (array of strings) -- detected technologies
  - `entry_points` (array of objects: {path, type, description})
  - `components` (array of objects: {name, path, purpose, public_api: [], dependencies: [], database_tables: []})
  - `infrastructure` (object: {deployment, ci, config_files: []})
- `source_material_index` (object) -- keys are "document/section" paths, values are objects: {source_files: [], staleness: "fresh"|"stale"|"unknown"}
- `staleness_report` (array of objects: {document, section, reason, changed_files: [], severity: "high"|"medium"|"low", suggested_action})
- `note_classifications` (array of objects: {note_id, audience, document, section, confidence: 0.0-1.0})
- `gap_analysis` (object: {undocumented_components: [], missing_for_audience: {audience_name: [component_names]}})
- `gsd_context` (object | null: {milestone, completed_phases: [], deviations: [], new_requirements_completed: []})

For each field, provide: description, type, example value, and whether required or optional. Use JSON code blocks for examples. Include a complete minimal example at the end showing the full structure.

**create-docs/references/style-guide.md** -- Cross-audience writing conventions. Organize into these sections:
1. **Universal Conventions** -- Active voice, present tense, no marketing language, version-independent phrasing
2. **Audience-Specific Conventions** -- Sub-sections for each of the 4 audiences:
   - End-users: Plain language, task-oriented, scannable (numbered steps, bullet lists), avoid implementation details
   - Developers: Code-first (examples before explanations), Stripe/Twilio-style, technical depth welcome, link to source
   - Agents: Explicit/machine-optimized, YAML frontmatter, absolute paths, no ambiguity, structured over prose
   - DevOps: Runbook structure (symptom-cause-fix), copy-paste-ready commands, include expected output
3. **Diataxis Classification** -- Brief explanation of the 4 Diataxis types (tutorial, how-to, reference, explanation) and which audience docs tend toward which type
4. **Section Conventions** -- How sections should start (context sentence), end (what's next), and handle optional content
5. **Formatting Standards** -- Heading levels, code block language tags, admonition format, link style

Keep the style guide practical and concise (~150-250 lines). Writer agents will reference this at generation time.
