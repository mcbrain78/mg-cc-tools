**add-note.py** -- Atomic note append following `codebase-health/scripts/add-finding.py` pattern:
- Shebang: `#!/usr/bin/env python3`
- Add `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` for lib imports
- `from lib.json_io import load_json, save_json`
- argparse with: `--inbox` (required, path to notes-inbox.json), `--text` (required, note text), `--phase` (optional, GSD phase context), `--file` (optional, active file context)
- Generate next ID: find max existing NOTE-NNN number, add 1, format as NOTE-{NNN:03d}. Handle gaps in numbering (use max+1, not length+1).
- Build note object per inbox schema (id, text, added as `datetime.now(timezone.utc).isoformat()`, context {phase, file}, classification: None, status: "pending")
- Append to notes array, save atomically
- Print confirmation to stderr: `Added note {id}: {text[:60]}...`
- Exit 0 on success, non-zero on error

**classify-note.py** -- Deterministic keyword-based classification:
- Shebang: `#!/usr/bin/env python3`
- argparse with: `--text` (required, note text to classify), `--inbox` (optional, path to inbox for context), `--note-id` (optional, if provided, updates the note's classification in the inbox file)
- Keyword dictionaries mapping terms to audiences:
  - devops: deploy, server, config, environment, docker, k8s, CI, CD, pipeline, monitoring, logs, restart, scale, terraform, ansible, nginx, port, SSL, certificate, uptime
  - developers: API, function, class, import, module, interface, type, return, async, callback, error handling, refactor, dependency, package, library, test, mock, stub
  - end-users: click, button, user, login, signup, dashboard, settings, profile, navigate, menu, page, screen, form, submit, download, install, start, guide, tutorial
  - agents: path, convention, pattern, file, directory, structure, naming, format, rule, constraint, invariant, absolute, frontmatter, schema
- For each audience, count keyword matches (case-insensitive). Score = matches / total_keywords_in_category.
- Top scoring audience wins. Confidence = top_score / (top_score + second_score) if second_score > 0, else 0.9 for clear single-audience match.
- Map audience to most likely document (first document in that audience's config list) and section ("general" as default).
- If `--note-id` and `--inbox` provided, load inbox, find note by id, update its classification field, save.
- Output JSON to stdout: `{"audience": "...", "document": "...", "section": "...", "confidence": 0.XX}`
- Exit 0 on success.

**merge-scan.py** -- Merge per-audience scan results following `codebase-health/scripts/merge-findings.py` pattern:
- Shebang: `#!/usr/bin/env python3`
- Add `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` for lib imports
- `from lib.json_io import load_json, save_json`
- argparse with: `--scan-dir` (required, directory containing per-audience scan JSON files), `--output` (required, path for merged docs-scan.json), `--project-name` (required, project name), `--root-path` (required, project root path), `--mode` (default "initial", choices ["initial", "update"])
- Glob `scan-dir/*.json` for per-audience scan files
- For each scan file, load and extract: source_material_index entries, staleness_report entries, note_classifications, gap_analysis data
- Merge strategy:
  - source_material_index: combine all keys, if duplicate key exists keep the one with more source_files
  - staleness_report: concatenate all entries, deduplicate by (document, section) keeping highest severity
  - note_classifications: concatenate all
  - gap_analysis: merge undocumented_components (union), merge missing_for_audience per audience (union)
  - project_model: take from first file that has it (scan step builds this once, not per-audience)
  - gsd_context: take from first file that has it
- Build output object with all top-level fields per schema. Use `datetime.now(timezone.utc).isoformat()` for scan_date.
- Save atomically via save_json
- Print summary to stderr: `Merged {N} scan files into {output}. {M} source material entries, {K} staleness issues.`
- Handle edge cases: empty scan-dir (produce valid minimal output), malformed JSON (skip with warning), missing fields in scan files (use empty defaults)
