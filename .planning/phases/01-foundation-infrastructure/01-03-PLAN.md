**File path detection:**
- Scan each .md file line by line
- Extract file paths using regex patterns:
  - Backtick-wrapped paths: `` `src/something.py` `` -- match `` `[^`]+\.[a-z]+` `` that look like file paths (contain `/` or end with common extensions: .py, .ts, .js, .md, .json, .yaml, .yml, .sh, .toml, .cfg, .env)
  - Code block paths: lines inside ``` blocks that reference files

- Skip anchors (anything starting with `#`)

- Check existence with `os.path.isfile()` or `os.path.isdir()`

**Symbol detection:**
- In code blocks, look for `ClassName.method_name()` or `module.function()` patterns
- For each symbol reference, search the corresponding source file (if file path is known) for the symbol name using simple text search
- This is best-effort -- focus on catching obvious broken references rather than full AST analysis

**Output:** JSON array of issue objects. Each has: `file` (the doc file), `line` (line number), `reference` (the path or symbol), `type` ("file_path" or "symbol"), `status` ("broken" or "valid"), `message` (human-readable description).

Print summary to stderr: `Checked {N} references in {M} files. {K} broken.`

    - Doc section with docs-meta timestamp newer than all source file changes shows as fresh
    - Doc section with no docs-meta comment is reported as "unknown" staleness
    - Source file that no longer exists is flagged as "broken reference" with high severity
    - Output is JSON array of staleness entries matching schema: [{document, section, reason, changed_files, severity, suggested_action}]
    - Works in a git repository (uses git log)
    - Gracefully handles non-git directory (reports all as "unknown")
    - Empty docs directory produces empty staleness array
  </behavior>
  <action>
**staleness-check.py** -- Git-based section freshness analysis:
- Shebang: `#!/usr/bin/env python3`
- Add `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` for lib imports
- `from lib.json_io import load_json, save_json`
- `from lib.git_helpers import git_file_changed_since, git_last_modified`
- argparse with: `--docs-dir` (required, directory containing generated docs), `--project-root` (required, project root for git operations), `--output` (optional, path to write JSON results; if omitted, print to stdout)

**Section parsing:**
- Walk all .md files in `--docs-dir` recursively
- For each file, parse docs-meta HTML comments: `<!-- docs-meta: {"last_updated": "...", "sources": [...]} -->`
- Use regex to extract the JSON from docs-meta comments
- Each docs-meta comment marks a section boundary (the heading above it)

**Staleness detection:**
- For each section with docs-meta:
  - Extract `last_updated` timestamp and `sources` file list
  - For each source file, use `git_file_changed_since(source, last_updated, repo_root=project_root)` to check if it changed
  - If ANY source file changed since last_updated: section is STALE
  - If NO source files changed: section is FRESH
  - If source file doesn't exist: BROKEN REFERENCE (high severity)
- For sections without docs-meta: staleness is UNKNOWN

**Severity assignment:**
- `high`: source file deleted (broken reference) or 3+ source files changed
- `medium`: 1-2 source files changed
- `low`: minor changes or unknown staleness

**Suggested actions:**
- high broken: "Remove or update references to deleted file {path}"
- high/medium stale: "Regenerate section -- {N} source files changed since {last_updated}"
- low/unknown: "Consider reviewing section freshness"

**Output:** JSON array of staleness entry objects per schema (document, section, reason, changed_files, severity, suggested_action). Only include entries that are NOT fresh (stale, broken, or unknown).

Print summary to stderr: `Checked {N} sections in {M} docs. {S} stale, {B} broken, {U} unknown.`

**Non-git handling:** Check if `--project-root` is a git repo by running `git rev-parse --git-dir`. If not, report all sections as "unknown" with reason "Not a git repository".
