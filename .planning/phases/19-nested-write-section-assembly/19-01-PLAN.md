<objective>
Extend write-section.py to support hierarchical child section emission via a `--parent` CLI flag, nested state format with `subsections`/`subsections_order`, recursive finalize that produces nested XML, and merge mode that handles all heading levels.

Purpose: Writers will call write-section.py once per heading (not just per `##` section), enabling per-heading provenance tracking and nested XML structure. This bridges the flat state format to the recursive xml_doc.py model built in Phase 18.

Output: write-section.py with --parent support, nested state format, recursive finalize/manifest/merge, and comprehensive test coverage.
</objective>

    Implement all nested section features in write-section.py. Changes organized by function:

    **1. New helper: `_resolve_parent(doc, parent_path)`**
    - Split parent_path on "/", walk doc["sections"] for first segment, then subsections for remaining segments
    - Return the parent section dict (which has subsections/subsections_order)
    - On miss at any segment: print error to stderr with path-so-far, sys.exit(1)

    **2. Update `section_write(args)`**
    - Add `subsections: {}` and `subsections_order: []` to every new section dict (WSA-07: always nested format)
    - Read `args.parent` (may be None)
    - If parent is set: call `_resolve_parent(doc, args.parent)` to get parent section, ensure parent has subsections/subsections_order keys, insert child section. If overwriting existing child, preserve its existing subsections and subsections_order (per Research Open Question 3)
    - If parent is None: existing top-level behavior, but with new subsections/subsections_order keys
    - Order preservation: append to subsections_order only if slug not already present

    **3. Update `parse_existing_sections(content)`**
    - Change regex from `r"(?=^## )"` to `r"(?=^#{2,5} )"` to split on all heading levels
    - Count `#` characters to determine depth (## = depth 0, ### = depth 1, etc.)
    - Use a path_stack list: trim to current depth, append slug, join with "/" to get path
    - Return (header, [(path, heading_line, body), ...]) -- note first element changes from slug to path

    **4. Update `finalize(args)` -- standard assembly path**
    - New helper `_state_sections_to_xml(doc_data)`: iterates sections_order, recursively converts each section to {slug, body, children} format for build_xml_doc
    - New helper `_state_section_to_xml_section(slug, section_data)`: returns {slug, body, children} recursively through subsections_order/subsections
    - Standard assembly (non-merge): walk state tree recursively to collect parts depth-first (header, then all section bodies in order)
    - XML build (non-merge): pass sections with children to build_xml_doc. After build, walk state tree recursively and call update_section_refs with full slash-separated paths

    **5. Update `finalize(args)` -- merge path (markdown)**
    - parse_existing_sections now returns paths, so merge matching uses path-based lookup
    - Build `new_sections` dict keyed by path (not slug): walk state tree recursively to collect all (path, content) pairs
    - Match existing sections by path, replace matched, preserve unmatched, append new

    **6. Update `finalize(args)` -- merge path (XML)**
    - Replace `get_section_slugs(tree)` with `get_section_paths(tree)` for existing path set
    - For each section in state (walked recursively): if path in existing paths, call `update_section_body(tree, path, content)`. If not, extract parent_path (everything before last "/") and leaf slug, call `add_section(tree, slug, content, parent_path=parent_path or None)` for top-level
    - Call `update_section_refs(tree, path, typed_refs)` with full paths

    **7. Update `finalize(args)` -- manifest building**
    - New helper `_collect_manifest_entries(sections, sections_order, prefix="")`: recursively yields (path, symbols, file_paths) for sections with non-empty refs, using slash-separated paths as keys
    - Replace flat iteration with recursive helper

    **8. Update `finalize(args)` -- _written_sections**
    - New helper `_collect_all_paths(sections, sections_order, prefix="")`: recursively collects all paths
    - Replace `list(sections_order)` with recursive path collection
