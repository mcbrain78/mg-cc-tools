Create split-scan-by-audience.py -- a CLI script that reads docs-scan.json and produces filtered per-audience or glossary view files with the same top-level key structure, so each writer agent reads a small focused file instead of the full 19k-token scan.

Purpose: Eliminate ~30 chunked reads per generate run by splitting the scan into audience-sized views (~5k tokens each).
Output: Working script with comprehensive test suite.

<feature>
  <name>split-scan-by-audience.py</name>
  <files>auto-doc/scripts/split-scan-by-audience.py, auto-doc/scripts/tests/test_split_scan_by_audience.py</files>
  <behavior>
    CLI interface:
    - `--input PATH` (required): path to docs-scan.json
    - `--output PATH` (required): path to write the view file
    - `--mode audience|glossary` (required): which filtering mode
    - `--audience NAME` (audience mode only): audience key (e.g., "developers")
    - `--documents LIST` (audience mode only): comma-separated uppercase document names (e.g., "ARCHITECTURE,DEVELOPER_GUIDE")

    Audience mode behavior:
    - Test 1: Filters source_material_index to only keys whose document prefix (text before first "/") is in --documents list
    - Test 2: Copies project_model and gsd_context verbatim from input
    - Test 3: Filters gap_analysis.missing_for_audience to only the target --audience key; preserves undocumented_components verbatim
    - Test 4: Omits staleness_report, note_classifications, scan_date, project, root_path, mode, last_generated from output
    - Test 5: Exits non-zero if --audience or --documents missing in audience mode
    - Test 6: Output has exactly 4 top-level keys: project_model, gsd_context, source_material_index, gap_analysis

    Glossary mode behavior:
    - Test 7: Preserves ALL source_material_index keys (no filtering by document)
    - Test 8: Reduces source_files arrays to basenames only (os.path.basename)
    - Test 9: Copies project_model and gsd_context verbatim
    - Test 10: Includes full gap_analysis (all audiences)
    - Test 11: Output has exactly 4 top-level keys

    Edge cases:
    - Test 12: Empty source_material_index produces empty dict in output (not error)
    - Test 13: Missing gap_analysis in input produces empty dict in output
    - Test 14: source_files with mixed path separators all reduce to basenames correctly
  </behavior>
  <implementation>
    Follow existing auto-doc script conventions:
    - sys.path.insert(0, ...) for lib imports
    - from lib.json_io import load_json, save_json
    - argparse with --input (dest="input_file"), --output, --mode choices=["audience", "glossary"]
    - Audience mode: --audience and --documents are required (validate and exit 1 if missing)
    - Glossary mode: --audience and --documents are ignored
    - filter_source_material(index, document_list) -> dict: key.split("/", 1)[0] in document_list
    - filter_gap_analysis(gap, audience) -> dict: keep undocumented_components, filter missing_for_audience
    - reduce_source_files_to_filenames(index) -> dict: os.path.basename on each source_files entry
    - build_view(data, keys_to_include) assembles the 4 top-level keys with .get() defaults
    - Tests use subprocess.run([sys.executable, SCRIPT_PATH, ...]) pattern per project convention
  </implementation>
</feature>
