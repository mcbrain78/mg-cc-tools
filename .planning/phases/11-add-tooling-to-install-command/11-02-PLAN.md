Purpose: These subcommands replace the LLM's unreliable state tracking across the multi-step install flow. The LLM no longer reconstructs the summary from memory or formats preflight/validation output -- Python does it deterministically from JSON files.

<feature>
  <name>Feature: Install plan, result tracking, and rendering subcommands</name>
  <files>install/scripts/mg-install-lib.py, install/scripts/tests/test_mg_install_lib.py</files>
  <behavior>
    _get_temp_dir:
    - Derives basename from target path (e.g. "/home/user/projects/road-runner" -> "road-runner")
    - Returns "/tmp/mg-install-{basename}" (or tempfile.gettempdir() equivalent)
    - Creates directory if it does not exist (os.makedirs with exist_ok=True)
    - Handles trailing slashes in target path (os.path.normpath)

    get-install-plan:
    - Input: --input (scan-status JSON), --tools (comma-separated), --output (optional)
    - Reads target from scan-status JSON (not a separate argument)
    - Determines pattern: copy_only (has_install_sh and not post_install), copy_configure (has_install_sh and post_install), execute_only (not has_install_sh and post_install)
    - Computes expected_action from status: available->"installed", update/modified/corrupt/adopted->"updated", current->"reinstalled"; appends " (configured)" for copy_configure and execute_only
    - Includes install_cmd: "bash ./{name}/install.sh --target \"{target}/.claude\"" for has_install_sh, null otherwise
    - Includes post_install path: "{name}/{post_install}" if post_install, null otherwise
    - Includes commands list from scan-status per tool
    - Skips tools not found in scan-status (graceful)
    - With --output: writes full plan to file, compact summary (tool+pattern+post_install per entry) to stdout
    - Without --output: full plan to stdout

    preflight --output:
    - Existing preflight subcommand gains --output argument
    - With --output: writes full result to file, compact {"all_passed": bool, "check_count": N, "details": path} to stdout
    - Without --output: unchanged behavior (full JSON to stdout)
    - os.makedirs(dirname, exist_ok=True) before writing

    render-preflight:
    - Input: --input (preflight JSON file)
    - Prints "Preflight checks:" header, blank line
    - For each check: "  [PASS] {id}    {version}    ({required_text})" or "  [FAIL] {id}    {error}    ({required_text})"
    - required_text: "required" or "optional" based on check's required field
    - Blank line, then summary: "  Required: N/M passed" and "  Optional: N/M passed" (only show optional line if optional checks exist)

    record-result:
    - Input: --file (results path), --tool (name), --success or --failed (mutually exclusive), --plan (install plan JSON path)
    - Creates file with [] if it doesn't exist
    - On --success: reads plan for tool's expected_action and commands, appends {"tool": name, "action": expected_action, "commands": [...]}
    - On --failed: appends {"tool": name, "action": "failed", "commands": []}
    - Reads existing array, appends, rewrites entire file

    render-summary:
    - Input: --results (install results JSON), --input (scan-status JSON), --preflight (optional preflight JSON)
    - Prints "mg-cc-tools -- INSTALL COMPLETE" header
    - Prints "  Target: {target}" from scan-status
    - Prints summary counts line: "  Installed: N  |  Updated: N  |  Failed: N"
    - Prints tool table with Tool, Action, Commands columns
    - For each result: tool name, action value, commands joined by ", " (or "--" if failed/empty)
    - If --preflight provided and has lsp check: prints "  Capabilities:" section with LSP status
    - If --preflight has failed optional checks: prints missing optional tools note

    render-validation:
    - Input: --input (validate JSON file)
    - If valid (issue_count == 0): prints "Post-install validation:\n  All checks passed -- no unresolved placeholders, all paths valid"
    - If issues: prints "Post-install validation:" then each issue as "  WARNING: {message}" then count line

    CLI argument convention (INST-55):
    - get-install-plan: --input, --tools, --output
    - render-preflight: --input
    - record-result: --file, --tool, --success/--failed, --plan
    - render-summary: --results, --input, --preflight
    - render-validation: --input
    - All stdlib-only (INST-57)
  </behavior>
  <implementation>
    1. Add _get_temp_dir(target_path) utility function near the top of the file (after constants). Uses os.path.basename(os.path.normpath(target_path)) for basename, os.path.join(tempfile.gettempdir(), f"mg-install-{basename}") for the path, os.makedirs with exist_ok=True.

    2. Add get_install_plan(scan_data, tool_names) function. Builds tools_by_name lookup from scan_data["tools"]. Iterates tool_names, determines pattern from has_install_sh/post_install, computes expected_action from status, builds install_cmd string, formats post_install path. Returns list of instruction dicts. See 11-RESEARCH.md "get_install_plan" code example.

    3. Modify cmd_preflight to accept optional args.output. When set: os.makedirs(dirname, exist_ok=True), write full result to file, compact summary to stdout. When not set: existing behavior (full JSON to stdout). Add --output to preflight argparse wiring.

    4. Add render_preflight(preflight_data) function. Iterates checks, prints [PASS]/[FAIL] lines with alignment, then summary counts. Separate required and optional counts.

    5. Add record_result(results_file, tool_name, success, plan_file) function. Creates file with [] if not found. Reads install plan to look up expected_action and commands for the tool. Appends entry. Rewrites file. See 11-RESEARCH.md "record_result" code example.

    6. Add render_summary(results_data, scan_data, preflight_data=None) function. Computes action counts from results. Prints header, target, counts, tool table. If preflight provided, prints capabilities and missing optional tools sections.

    7. Add render_validation(validate_data) function. Checks valid/issue_count, prints appropriate output.

    8. Add all CLI handlers (cmd_get_install_plan, cmd_render_preflight, cmd_record_result, cmd_render_summary, cmd_render_validation) following the existing pattern.

    9. Wire all into main() argparse. Ensure --input is used consistently for scan-status across all subcommands (INST-55). render-summary uses --results, --input, --preflight.
