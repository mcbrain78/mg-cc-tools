Plan 01 subcommands:
```
scan-status --source ./ --target $TARGET --output $TMP/scan-status.json --auto-adopt
  -> writes full scan to file, compact JSON to stdout

  -> prints scenario-appropriate menu to stdout (echo verbatim)

resolve-action --input $TMP/scan-status.json --selection "<response>"
  -> returns JSON: {"action": "install", "tools": [...]}
  ->            or {"action": "select_specific"}
  ->            or {"action": "edit_standard"}
  ->            or {"action": "check_capabilities"}
  ->            or {"error": "..."}
```

Plan 02 subcommands:
```
get-install-plan --input $TMP/scan-status.json --tools "t1,t2" --output $TMP/install-plan.json
  -> writes plan to file, compact JSON (tool+pattern+post_install) to stdout

preflight --source ./ --target $TARGET --tools "t1,t2" --output $TMP/preflight.json
  -> writes results to file, compact {"all_passed": bool} to stdout

render-preflight --input $TMP/preflight.json
  -> prints formatted PASS/FAIL output (echo verbatim)

record-result --file $TMP/install-results.json --tool <name> --success/--failed --plan $TMP/install-plan.json
  -> appends to results file (no output to echo)

render-validation --input $TMP/validate.json
  -> prints formatted PASS/WARNING output (echo verbatim)

render-summary --results $TMP/install-results.json --input $TMP/scan-status.json --preflight $TMP/preflight.json
  -> prints formatted summary table (echo verbatim)
```

  <action>
    Write install.md FROM SCRATCH (do not try to incrementally edit the 475-line original). The new prompt follows a strict pattern: run Python -> echo output -> [get user input -> run Python] -> next step.

    Structure the prompt as follows:

    **Frontmatter:** Keep existing name, description, allowed-tools.

    **Header section (~15 lines):**
    - Title and role description (you are the installer, you run from mg-cc-tools dir)
    - Prerequisites check (test -f ./pyproject.toml)
    - Set MG_INSTALL_LIB path
    - Define TMP directory: `TMP="/tmp/mg-install-$(basename "$TARGET_PATH")"` (per INST-56)

    **Display rule (~5 lines, per INST-54):**
    A single consolidated rendering rule replacing all per-subcommand echo instructions:
    - `render-*` subcommand output: echo COMPLETE stdout verbatim as a fenced code block (Bash output is collapsed in UI). Never drop, truncate, or summarize any line.
    - Other subcommand output: machine-readable JSON -- do NOT echo to user. Parse it for the next step.

    **Step 1: Target Selection (~30 lines):**
    Keep from existing prompt nearly verbatim -- this is LLM territory (AskUserQuestion, sibling discovery, manual path entry, .claude dir creation). After target is determined, set TMP path.

    **Step 2: Status Scan (~10 lines):**
    ```bash
    python3 "$MG_INSTALL_LIB" scan-status --source ./ --target "$TARGET_PATH" --output "$TMP/scan-status.json" --auto-adopt
    ```
    Then: `python3 "$MG_INSTALL_LIB" render-status-table --input "$TMP/scan-status.json"`
    Echo the table output per display rule.
    If auto_adopted list is non-empty in stdout JSON, mention which tools were adopted before the table.
    NOTE: Step 2b (migration check) is GONE -- --auto-adopt handles it.

    **Step 3: Action Selection (~40 lines):**
    Run render-action-menu, echo output. Get user response. Run resolve-action with --selection.
    - If action is "select_specific": run render-tool-picker, echo, get response, run resolve-tool-selection
    - If action is "edit_standard": run the Edit Standard Install List sub-flow (keep from existing prompt -- ~37 lines of interactive toggle logic, this stays in LLM territory)
    - If action is "check_capabilities": skip to Step 5 then Step 8
    - If action has "tools" list: proceed with that list
    - If action has "error": show error, re-prompt (try resolve-tool-selection as fallback for free text)

    **Step 4: Preflight Checks (~10 lines):**
    ```bash
    python3 "$MG_INSTALL_LIB" preflight --source ./ --target "$TARGET_PATH" --tools "tool1,tool2" --output "$TMP/preflight.json"
    ```
    Check all_passed from compact stdout. If false: STOP with fix instructions from preflight JSON. If true: run render-preflight, echo output.

    **Step 5: Capability Check (~8 lines):**
    Keep from existing prompt -- simple conditional on lsp check result from preflight JSON. Only shown if lsp check was run.

    **Step 6: Execute Installs (~40 lines):**
    Run get-install-plan to get the plan. Read compact stdout for the loop.
    For each tool in compact plan:
    - If pattern has install_cmd: run bash install.sh
    - If pattern has post_install: read file, spawn Agent
    - If execute_only and succeeded: call update-manifest
    - After each tool: call record-result with --success or --failed
    - On failure: STOP. Show which tools succeeded, which failed, which not attempted.
    Display progress inline as each tool completes.

    **Step 7: Post-Install Validation (~8 lines):**
    ```bash
    python3 "$MG_INSTALL_LIB" validate --target "$TARGET_PATH" --tools "tool1,tool2" --source ./ --output "$TMP/validate.json"
    ```
    Run render-validation, echo output.

    **Step 8: Summary (~5 lines):**
    ```bash
    python3 "$MG_INSTALL_LIB" render-summary --results "$TMP/install-results.json" --input "$TMP/scan-status.json" --preflight "$TMP/preflight.json"
    ```
    Echo output per display rule.

    **Key Constraints section (~10 lines):**
    Keep relevant constraints from existing prompt. Remove any that are now handled by Python (scenario selection, pattern determination, summary construction).

    **What gets DELETED (per CONTEXT.md):**
    - Three scenario menu templates (A/B/C) -- replaced by render-action-menu
    - Option-to-action mapping tables -- replaced by resolve-action
    - Step 2b adoption check (entire section) -- replaced by --auto-adopt
    - Per-tool pattern determination (if/elif on fields) -- replaced by get-install-plan
    - Preflight result formatting -- replaced by render-preflight
    - Summary table construction from memory -- replaced by render-summary + record-result
    - Validation result formatting -- replaced by render-validation
    - Per-subcommand echo instructions (multiple) -- replaced by single display rule
    - Hardcoded /tmp/mg-*.json paths -- replaced by $TMP per-target directory

    **What STAYS in prompt (per CONTEXT.md):**
    - Step 1 target selection via AskUserQuestion
    - Step 3 Edit Standard Install List sub-flow (~37 lines, interactive toggle)
    - Step 5 Capability check display (simple conditional)
    - Step 6 Agent spawning for post-install.md
    - Step 6 POST-INSTALL marker parsing
    - Step 6 Stop-on-error decision
    - Free text fallback when resolve-action returns error

    TARGET: Under 250 lines. If you exceed 250, cut explanatory prose -- the Python subcommands are self-documenting.
