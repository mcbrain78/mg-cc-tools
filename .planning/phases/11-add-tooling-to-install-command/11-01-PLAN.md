Implement the core scenario logic and action subcommands for the install command refactor: `_determine_scenario()` shared helper, `render-action-menu` subcommand, `resolve-action` subcommand, and `--auto-adopt` flag on `scan-status`.

<feature>
  <name>Feature: Shared scenario logic and action subcommands</name>
  <files>install/scripts/mg-install-lib.py, install/scripts/tests/test_mg_install_lib.py</files>
  <behavior>
    _determine_scenario:
    - Returns "A" when summary.installed_total == 0
    - Returns "B" when summary has update > 0
    - Returns "B" when summary has modified > 0
    - Returns "B" when summary has corrupt > 0 (INST-51 behavior change)
    - Returns "B" when summary has adopted > 0 (INST-51 behavior change)
    - Returns "C" when installed_total > 0 and no update/modified/corrupt/adopted

    scan-status --auto-adopt:
    - Without --auto-adopt flag, scan-status output has no auto_adopted field (backward compat)
    - With --auto-adopt and manifest exists, no adoption happens (flag ignored)
    - With --auto-adopt and no manifest, calls adopt_tools() before computing statuses
    - Output includes "auto_adopted" list with adopted tool names when adoption occurred
    - Compact stdout (--output mode) also includes auto_adopted field

    render-action-menu:
    - Scenario A: prints 3 options with standard tool count, "Type a number, or tool names"
    - Scenario B: prints 5 options with attention count and available count, "Type a number, tool names, or 'all'"
    - Scenario C: prints 4 options with remaining standard count, "Type a number, tool names, or 'all'"
    - All scenarios start with "What would you like to do?"

    resolve-action:
    - Scenario A option 1: returns {"action": "install", "tools": [all standard tools]}
    - Scenario A option 2: returns {"action": "select_specific"}
    - Scenario A option 3: returns {"action": "edit_standard"}
    - Scenario B option 1: returns {"action": "install", "tools": [tools needing attention]}
    - Scenario B option 2: returns {"action": "install", "tools": [attention + missing standard]}
    - Scenario B option 3: returns {"action": "install", "tools": [missing standard only]}
    - Scenario B option 4: returns {"action": "edit_standard"}
    - Scenario B option 5: returns {"action": "check_capabilities"}
    - Scenario C option 1: returns {"action": "install", "tools": [remaining available standard]}
    - Scenario C option 2: returns {"action": "install", "tools": [all non-excluded]}
    - Scenario C option 3: returns {"action": "edit_standard"}
    - Scenario C option 4: returns {"action": "check_capabilities"}
    - Non-numeric input delegates to resolve_tool_selection()
    - Invalid menu number returns {"error": "..."}

    CLI wiring:
    - render-action-menu accepts --input (required)
    - resolve-action accepts --input (required) and --selection (required)
    - scan-status accepts --auto-adopt (optional flag)
    - All new subcommands are stdlib-only (INST-57)
  </behavior>
  <implementation>
    1. Add _determine_scenario(scan_data) as a private helper between the render-status-table section and the argparse section. It reads scan_data["summary"] counts and returns "A"/"B"/"C".

    2. Add render_action_menu(scan_data) that calls _determine_scenario(), computes dynamic counts (attention_count, standard_available, standard_total) by iterating tools array, then prints the appropriate menu. Follow the exact menu text from 11-CONTEXT.md decisions.

    3. Add resolve_action(scan_data, selection_text) that calls _determine_scenario(), parses the selection (number check first, then delegate to resolve_tool_selection for non-numeric), and returns the appropriate action dict. Use a _resolve_menu_option(scenario, num, tools, summary) helper for the number-to-action mapping.

    4. Modify cmd_scan_status to accept args.auto_adopt. When set and scan_status result shows manifest_exists=False, call adopt_tools(args.source, args.target) first, then re-run scan_status. Add "auto_adopted" to the result dict. When --output mode, include auto_adopted in both file output and compact summary.

    5. Add cmd_render_action_menu and cmd_resolve_action CLI handlers following the existing pattern (open --input, call function, print/json.dump).

    6. Wire all three into main() argparse with --input for both renderers, --selection for resolve-action, and --auto-adopt flag on scan-status.

    Research code examples: See 11-RESEARCH.md "Code Examples" section for _determine_scenario, render_action_menu, and resolve_action reference implementations. Adapt (do not copy blindly) -- the test behaviors above are authoritative.
