Key transformations from the original command:

1. **Strip YAML frontmatter** -- no name/description/allowed-tools header
2. **Remove Step 0 (source sync check)** -- per CONTEXT.md: "Remove Step 0 sync check -- always reading from source now." The subagent reads patches directly from source, so there is no installed copy to sync.
3. **Replace path placeholders:**
   - `{PATCHES_DIR}` and `{SOURCE_PATCHES_DIR}` -> reference "the source directory" from prompt prefix + `/gsd-patches/patches/`
   - `$ARGUMENTS` -> read target project path from prompt prefix

   - Remove `<target project>/.claude/commands/mg/apply-gsd-patches.md` if it exists
   - Remove `<target project>/.claude/gsd-patches/` directory if it exists
   - Log what was cleaned up
5. **Keep all patch application logic** from the original:
   - Step 1: Resolve target project (simplified -- path from prompt prefix)
   - Step 2: Discover patches (read *.md from source directory's gsd-patches/patches/)
   - Step 3: Parse each patch file for anchor/replace pairs
   - Step 4: For each patch, find the target file, locate anchor text, apply replacement
   - Step 5: Handle conflicts (ask user via AskUserQuestion if anchor not found)
   - Step 6: Summary of applied/skipped/conflicted patches
6. **Add completion section** with POST-INSTALL: SUCCESS / POST-INSTALL: FAILED markers
7. **Reference all paths via natural language** from the prompt prefix -- no shell variables, no sed placeholders

The post-install.md should be readable as a complete standalone document that a Claude subagent can execute with no prior context beyond the prompt prefix paths.
