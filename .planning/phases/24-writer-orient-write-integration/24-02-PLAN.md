    - Add: `refined_template_path` (Path to the project-specific refined template for this document)
    - Add: `state_file_path` (Path to the next-heading.py state file for this document, scoped per document)
    - Add: `scripts_dir` (Absolute path to auto-doc/scripts/ for calling next-heading.py)

    **Rewrite Process section entirely** following this structure:

    1. **Read context** (once per invocation): Load scan data JSON from scan_data_path. Read project model from project_model_path. Read style guide. Read glossary (may not exist on initial).

    2. **For each assigned document:**

       a. Write the document header to `{TMP_DIR}/header-devops-{DOCUMENT}.md` (same as current -- ownership comment, DIATAXIS, AUDIENCE, H1 heading).

       b. First call to next-heading.py:
          ```bash
          python3 {SCRIPTS_DIR}/next-heading.py \
            --state-file {STATE_FILE_PATH} \
            --template {REFINED_TEMPLATE_PATH} \
            --scan-file {project_root}/.mg/docs/docs-scan.json \
            --document {DOCUMENT}
          ```
          Parse the JSON output.

       c. **LOOP** until done:
          - **If type = "orient":**
            - Note the `heading_outline` for structural context (tells the writer what subsections are coming).
            - Read each file from `source_files`: use `get_symbols_overview` (depth: 1) for Python files, `find_symbol` with `include_info: true` for signatures/docstrings, `include_body: true` for deployment/config functions. Fall back to `Read` for non-code files (yaml, toml, Dockerfile, .env.example, shell scripts, SQL). Prefer `include_info: true` for deployment and configuration symbols; use `include_body: true` for configuration parsing and environment variable handling.
            - Call next-heading.py again for the next response.
          - **If type = "write":**
            - Split `heading_path` on `/`: last segment = `section_slug`, everything before = `parent_path`.
            - Generate content for this heading:
              - Use the `purpose` field as the generation goal (what this section must accomplish).
              - Use the `example` field as the format template (what "good" looks like -- structure, not content).
              - Draw on source code already read during the orient phase.
              - Follow style guide conventions and use glossary terms consistently.
              - In update mode: skip if section not in update_sections.
              - If standing notes exist for this section, incorporate naturally.
            - Write content to `{TMP_DIR}/section-devops-{DOCUMENT}-{heading_path_dashed}.md` (replace `/` with `-` in heading_path for filename).
            - Write typed_refs to `{TMP_DIR}/refs-devops-{DOCUMENT}-{heading_path_dashed}.json`.
            - Call write-section.py:
              ```bash
              python3 {SCRIPTS_DIR}/write-section.py \
                --state-file {TMP_DIR}/write-state-devops.json \
                --document {DOCUMENT} \
                --section {section_slug} \
                [--parent {parent_path}] \
                --content-file {TMP_DIR}/section-devops-{DOCUMENT}-{heading_path_dashed}.md \
                --refs-file {TMP_DIR}/refs-devops-{DOCUMENT}-{heading_path_dashed}.json \
                [--header-file {TMP_DIR}/header-devops-{DOCUMENT}.md] \
                --project-root {project_root}
              ```
              Pass `--parent {parent_path}` only when heading_path contains `/`.
              Pass `--header-file` ONLY on the very first `##` section of the document (first write response where level=2 and no prior write for this document).
            - Call next-heading.py again for the next response.
          - **If done = true:**
            - Log `headings_processed` count.
            - Exit loop for this document.
          - **If exit code non-zero or malformed JSON:** Log error, retry once with same args (state file tracks position). If retry fails, log and continue to next document.

       d. Post-processing checks (same as current):
          - Rollback verification -- verify matching rollback for every deployment procedure.
          - Command output verification -- verify success AND failure output documented.
          - Placeholder check -- no unexplained `<placeholder>` syntax.

    3. **Propose new terms** -- same as current (JSON array to terms-devops.json).

    **Include concrete heading_path splitting examples** in the Process section (3 examples: ##, ###, ####) per Pitfall 2 in RESEARCH.md.

    **Typed refs format and ref type table:** Keep the same typed_refs format section and ref type table from the current agent -- these are unchanged.

    **Refs scoping rule:** Keep the same scoping rule -- each heading's refs are scoped to only that heading's content.

    **Key instruction to include verbatim:** "You never decide what headings to create -- that is the template's job via next-heading.py. You never worry about document-level structure -- that is the heading outline. You focus entirely on reading source code and writing good prose with accurate refs."
