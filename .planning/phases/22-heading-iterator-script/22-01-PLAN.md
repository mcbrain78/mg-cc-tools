```python
def slugify_heading(heading):
    """Convert a heading to a slug: lowercase, spaces to hyphens, strip non-alnum."""
    slug = heading.strip().lower()
    slug = re.sub(r"[^a-z0-9\s-]", "", slug)
    slug = re.sub(r"[\s]+", "-", slug)
    return slug.strip("-")
```

<feature>
  <name>next-heading.py heading iterator</name>
  <files>auto-doc/scripts/next-heading.py, auto-doc/scripts/tests/test_next_heading.py</files>
  <behavior>
    CLI interface (HIT-01):
    - `--state-file`, `--template`, `--scan-file`, `--document` are all required
    - Missing any argument exits with argparse error (exit code 2)

    Template parsing and state persistence (HIT-02):
    - First call with no existing state file: parses refined template, extracts heading tree with PURPOSE and EXAMPLE per heading (multi-line HTML comments), builds emission queue, persists to state file
    - Subsequent calls: reads state from file, does NOT re-parse template
    - Multi-line `<!-- PURPOSE: ... -->` and `<!-- EXAMPLE: ... -->` comments are correctly extracted
    - Headings inside `<!-- EXAMPLE: -->` blocks are NOT treated as real template headings

    Orient response (HIT-03):
    - Emitted at each `##` section boundary (before any writes for that section)
    - Format: `{"type": "orient", "section": "{slug}", "heading_outline": [...], "source_files": [...]}`
    - `heading_outline` is depth-first list of heading_paths for that section (slugs only)
    - `source_files` looked up from scan file via `{DOCUMENT}/{section-slug}` key; empty list if key missing

    Write response (HIT-04):
    - Emitted for every heading including the `##` itself
    - Format: `{"type": "write", "heading_path": "...", "level": N, "purpose": "...", "example": "..."}`
    - `##`-level writes: `parent_path` key is ABSENT (not null, absent)
    - `###`+ writes: `parent_path` present (e.g., `"parent_path": "infrastructure-overview"`)

    Done response (HIT-05):
    - Format: `{"done": true, "headings_processed": N}`
    - N = total number of write responses emitted (not orient)
    - Calling after done keeps returning done (idempotent)

    Depth-first ordering (HIT-06):
    - Sequence: orient, write(##), write(###), write(####), ..., orient, write(##), ..., done
    - Source files appear ONLY in orient responses, NEVER in write responses

    heading_path convention (HIT-07):
    - Slash-separated: `{section-slug}/{child-slug}/{grandchild-slug}`
    - Last segment -> write-section.py `--section`
    - Preceding segments -> write-section.py `--parent`
    - `##`-level headings have no `/` in path

    Edge cases:
    - Template with no ## headings: immediate done with headings_processed=0
    - Missing scan file key for a section: orient has source_files=[] (no error)
    - Template file doesn't exist: exit 1 with error to stderr
    - Scan file doesn't exist: exit 1 with error to stderr
  </behavior>
  <implementation>
    Follow next-section.py's state machine pattern exactly:

    1. Parse args: --state-file, --template, --scan-file, --document (all required)
    2. Load state via load_json(state_file). If None, initialize:
       a. Read template file, parse headings (## through ####) extracting PURPOSE and EXAMPLE
       b. Strip HTML comments before heading detection to avoid Pitfall 3 (headings in EXAMPLE blocks)
       c. Read scan file, extract source_material_index
       d. Build flat emission queue: for each ## section -> orient response, then write responses depth-first
       e. Append done response at end
       f. State = {"queue": [...], "index": 0}
    3. Read queue[index]. If response is done or index >= len(queue), emit done and return
    4. Emit response as JSON to stdout
    5. Advance index, save state

    Key implementation details:
    - Copy slugify_heading() verbatim from write-section.py for heading_path compatibility
    - Template parsing: extract comments FIRST (keyed by line position), then split on headings
    - Use regex `r'<!--\s*PURPOSE:\s*(.*?)-->'` with re.DOTALL for multi-line PURPOSE extraction
    - Use regex `r'<!--\s*EXAMPLE:\s*(.*?)-->'` with re.DOTALL for multi-line EXAMPLE extraction
    - Discard everything before first ## heading (preamble: DIATAXIS, AUDIENCE, # Title, docs-meta)
    - Build heading tree: ## sections contain ### children which contain #### grandchildren
    - Flatten to emission queue with orient at ## boundaries per the flat list approach from RESEARCH.md Pitfall 5
  </implementation>
</feature>
