**1. Agent prefix resolution helper:**
- `resolve_agent_prefix(data, prefix)` -> returns (process_entry, process_id) or raises SystemExit
- Match prefix against all process IDs in `data["processes"]`
- Zero matches: print `"No agent matching prefix '{prefix}'"` and exit 1
- Multiple matches (SAN-16): print `"Ambiguous prefix '{prefix}' -- matches {id1[:8]}, {id2[:8]}, {id3[:8]}. Use a longer prefix."` and exit 1
- Exactly one match: return the process entry and full ID

**2. cmd_agent(data, session_file, args):**
- Resolve `args.prefix` to a single process via `resolve_agent_prefix`
- Display header: `Agent {id[:8]} -- {status} -- {duration} -- {message_count} messages`
- Prompt: First user message content (full text, this is the agent's task)
- Interleave messages in execution order. For each message in `process["messages"]`:
  - **Assistant text**: `msg[{N}] asst: {text}` -- show full text for summary, truncated to first 20 lines with `... ({remaining} more lines, use msg {prefix} {N} for full)` indicator
  - **Assistant tool_use**: `msg[{N}] -> {tool_name}({input_summary_80_chars})` -- summary mode, show tool name and input summary only
  - **User tool_result**: `msg[{N}] <- {tool_name}: {status}` where status is ok/error/persisted. For errors, show first 3 lines of error. For persisted, show `(persisted, {size} bytes)`. Do NOT show full content (summary command).
  - **User text**: `msg[{N}] user: {first 80 chars}`
- Message indices (N) are 0-based within the process message list
- Apply pagination to the list of display entries
- Wire into argparse: replace stub handler for `agent` subcommand

**3. cmd_msg(data, session_file, args):**
- Two forms: `msg <N>` (orchestrator) and `msg <agent_prefix> <N>` (agent process)
- Parse args: if `args.agent_prefix` is set, resolve agent and use process messages. Otherwise use `data["messages"]`.
- Validate index is in range. If out of range: `"Message index {N} out of range (0-{max})"` and exit 1.
- Display the target message with +/-2 context:
  - For each message in range [N-2, N+2] (clamped to valid range):
    - Separator line: `--- msg[{i}] {role} {timestamp} ---` (mark target message with `***`)
    - Full content display (this is a CONTENT command per SAN-24):
      - Text blocks: full text
      - Tool_use blocks: tool name + full input JSON (pretty-printed, truncated at 100 lines)
      - Tool_result blocks: full result text with `recover_persisted(text, session_dir)` applied
    - Strip `<usage>` blocks from display
- Wire into argparse: replace stub handler for `msg` subcommand. Argparse setup: `msg` subcommand with positional `index` (int) and optional `--agent` flag taking a prefix string.

    - Scope filters: --scope orchestrator, --scope agents, --scope agent:<prefix>
    - Default scope: search everything
    - Results show: location (orchestrator/agent prefix), msg[N] reference, matched line with context
    - Paginated with default 20
  </behavior>
  <action>
**1. cmd_search(data, session_file, args):**
- Parse `args.pattern` as a case-insensitive regex via `re.compile(args.pattern, re.IGNORECASE)`
- If regex is invalid, print error and exit 1
- Determine search scope from `args.scope`:
  - `None` (default): search orchestrator messages + all process messages
  - `"orchestrator"`: search only `data["messages"]`
  - `"agents"`: search only process messages (all processes)
  - `"agent:<prefix>"`: resolve prefix via `resolve_agent_prefix`, search only that process's messages
- For each message in scope:
  - Extract searchable text:
    - Assistant text content blocks -> search text
    - Tool_use input blocks -> search `json.dumps(input, indent=2)` (search the serialized input)
    - Tool_result content blocks -> apply `recover_persisted(text, session_dir)` BEFORE matching (lazy recovery per CONTEXT.md). Search the recovered/cleaned text.
  - If pattern matches anywhere in the extracted text:
    - Build a result entry:
      - Header: `[{location}] msg[{N}]` where location is "orch" or "agent:{id[:8]}"
      - Matched lines: Show the matching line(s) with 1 line of context above and below. Highlight match position by showing `>>> {matched_line}` prefix.
      - If multiple matches in same message, show each matched line
- Collect all result entries, apply pagination
- Wire into argparse: replace stub handler for `search` subcommand. Add `--scope` argument with choices validation.
