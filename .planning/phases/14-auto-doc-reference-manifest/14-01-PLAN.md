  <action>
Follow the add-verify-finding.py pattern exactly. Key differences from that script:

1. CLI args: `--input` (temp file with entry JSON) and `--manifest` (target manifest file, NOT --findings-file)
2. Required fields: `document` and `section` only (not 7 fields like verify findings)
3. Validation: at least one of `symbols` or `file_paths` must be non-empty, UNLESS `section == "_written_sections"` (metadata entry)
4. For `_written_sections` metadata: require `sections_written` field instead of symbols/file_paths
5. Operation is UPSERT by (document, section) key, not APPEND to array
6. Manifest structure: `{"audience": "...", "generated": "...", "documents": {DOC: {section: {symbols: [...], file_paths: [...]}}}}}`
7. If `sections_written` is present in input, preserve it in the manifest entry
8. Confirmation to stderr: "Added manifest entry: {document}/{section}"

Use subprocess-based tests matching the test_add_verify_finding.py pattern (no direct imports of kebab-case modules). Test classes: TestAddManifestEntryBasic, TestAddManifestEntryUpsert, TestAddManifestEntryRejection, TestAddManifestEntryCLI, TestAddManifestEntryMetadata.

Section title: `## Reference Manifests`

Content to document:
- Location: `.mg/docs/reference-manifests/{audience}.json`
- One file per audience (developers, end-users, agents, devops)
- Top-level fields: `audience` (string), `generated` (ISO timestamp), `documents` (object)
- Documents structure: `{DOCUMENT_NAME: {section-slug: {symbols: [...], file_paths: [...]}}}`
- `symbols`: unqualified code identifiers (function names, class names, constants) -- never dotted paths
- `file_paths`: files and directories referenced, relative to project root
- Upsert key: `(document, section)` pair
- Lifecycle: created by generate pipeline, consumed by verify pipeline
- Initial mode: all manifests cleared before generation
- Update mode: only regenerated sections upserted, others preserved
- `_written_sections` metadata: transient entry used for stale section cleanup, stripped before persisting

Include a complete minimal example JSON showing one audience manifest with two documents and multiple sections.

Do NOT modify any existing sections. Only append the new section.
