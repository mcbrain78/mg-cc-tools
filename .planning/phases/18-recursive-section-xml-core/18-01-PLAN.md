<feature>
  <name>Recursive Section XML Model</name>
  <files>auto-doc/scripts/lib/xml_doc.py, auto-doc/scripts/tests/test_xml_doc.py</files>
  <behavior>
    # Build (XML-01, XML-02, XML-07)
    - build_xml_doc with flat sections (children: []) produces same structure as before
    - build_xml_doc with nested children produces recursive <section> elements
    - 3-level nesting (## -> ### -> ####) produces 3 levels of <section> elements
    - Each section body contains only its own prose, not child content
    - children defaults to [] when key is absent in input dict (backward compat)

    # Parse (XML-04)
    - parse_xml_doc on nested XML returns dicts with "children" key (list)
    - Leaf sections have children: []
    - Nested sections have populated children lists
    - Round-trip: build -> serialize -> parse yields equivalent nested structure

    # walk_sections (XML-04)
    - walk_sections([]) yields nothing
    - walk_sections on flat sections yields ("slug", section) for each
    - walk_sections on nested sections yields depth-first (path, section) tuples
    - Paths are slash-separated: "parent/child", "parent/child/grandchild"

    # get_section_paths (XML-05, renamed from get_section_slugs)
    - Returns flat list of slash-separated paths for ALL sections at all depths
    - Bare slugs for top-level sections (backward compatible)
    - "parent/child" for nested sections

    # _find_section_by_path (XML-05)
    - Single-segment path finds top-level section (backward compat)
    - Multi-segment path walks tree level by level
    - Returns None on miss (not raise)

    # _find_section (XML-05)
    - Raises ValueError on miss (wraps _find_section_by_path)
    - Works with both bare slugs and slash-separated paths

    # update_section_body (XML-05)
    - Accepts slash-separated path parameter (was slug)
    - Updates correct nested section body via path
    - Raises ValueError for missing path

    # update_section_refs (XML-03, XML-05)
    - Accepts slash-separated path parameter (was slug)
    - Updates correct nested section refs via path
    - Refs per-section only, not inherited

    # add_section (XML-06)
    - Without parent_path: appends to root (backward compat)
    - With parent_path: appends as child of resolved parent
    - Raises ValueError for missing parent_path
    - Raises ValueError for duplicate sibling slug

    # Round-trip fidelity (XML-09)
    - Parameterized at 1, 2, 3 levels of nesting
    - Slugs, bodies, refs, and children all preserved
  </behavior>
  <implementation>
    TDD cycle: write tests first (RED), then implement functions (GREEN), then clean up (REFACTOR).

    Implementation order for GREEN phase (bottom-up from leaf helpers):
    1. _find_section_by_path -- pure navigation, returns None on miss
    2. _find_section -- raising wrapper around _find_section_by_path
    3. _build_section -- recursive helper for build_xml_doc
    4. build_xml_doc -- uses _build_section for recursive nesting
    5. _parse_section -- recursive helper for parse_xml_doc
    6. parse_xml_doc -- uses _parse_section for recursive parsing
    7. walk_sections -- depth-first generator yielding (path, section_dict)
    8. get_section_paths -- uses _collect_paths recursive helper (renamed from get_section_slugs)
    9. update_section_body -- change slug param to path, use _find_section
    10. update_section_refs -- change slug param to path, use _find_section
    11. add_section -- add optional parent_path, validate sibling uniqueness

    Key patterns from RESEARCH.md:
    - _build_section uses etree.SubElement recursion (refs + body BEFORE children)
    - _parse_section uses section_el.findall("section") for direct children only
    - _find_section_by_path iterates path.split("/") matching child slugs
    - walk_sections: yield (path, section), then yield from walk_sections(children, path)
    - build_xml_doc defaults missing children to []: section.get("children", [])
  </implementation>
